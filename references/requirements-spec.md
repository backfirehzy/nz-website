# 需求规格说明书

> 项目：新西兰建筑设计公司官网（外包开发）
> 状态：草稿 v0.3 —— 需求逐项沟通中，本文档随沟通结论持续更新
> 最近更新：见 git 提交历史

## 1. 项目概述

为一家新西兰本地建筑设计公司开发以展示为主的官方网站。网站用于展示公司案例、服务与团队信息，并提供联系表单获取客户询盘。不涉及用户登录、在线交易等复杂功能。

## 2. 项目范围

### 范围内（In Scope）

- 中英双语展示型官网
- 案例（Projects）展示
- 新闻 / 博客模块
- 团队（Team）、服务（Services）页面
- 联系信息表单（含文件上传）
- 客户员工可自助修改内容的可视化后台（CMS）
- 响应式布局（桌面 + 移动端）
- 基础 SEO（收录、sitemap、分享卡片）

### 范围外（Out of Scope，除非后续补充）

- 用户注册 / 登录 / 会员体系
- 在线支付、电商功能
- 多语言（除中英以外的第三种语言）
- 服务器端复杂业务逻辑

### 页面清单（暂定）

首页 / 案例（Projects）/ 新闻（News）/ 团队（Team）/ 服务（Services）/ 联系（Contact）

> 注：关于（About）页未单独列出，如需可并入首页或后续补充。

### 设计稿约定

最终设计稿由**客户**提供；开发阶段一律使用占位图片与占位文案代替，不影响功能开发进度。

## 3. 功能需求

### FR-01 中英双语

- 全站所有页面元素（导航、正文、按钮、表单提示、页脚等）均要求双语显示、可切换。
- 新闻 / 博客文案由客户编写，同样要求双语。
- URL 按语言区分（见 5.1 已拍板决策）。

### FR-02 案例展示

- 案例列表页（支持按项目类型筛选）+ 案例详情页。
- 数据量级：**不超过 100 个案例**。
- 字段（已定稿，除标题外全部可选）：

| 字段 | 说明 |
|---|---|
| 标题 | 双语 |
| 描述 | 双语，富文本 |
| 封面图 | 列表页卡片用 |
| 图集 | 仅图片，走 Sanity 图片 CDN |
| 视频链接 | 可选；粘贴 YouTube / Vimeo / Bilibili 分享链接，前端嵌入播放器 |
| 地点 | 如 Auckland |
| 年份 | 项目完成年份 |
| 面积 | 如 350 m² |
| 项目类型 | 住宅 / 商业 / 公共建筑，用于列表筛选 |

- 视频**不自建托管**：采用第三方平台嵌入，零存储与带宽成本（自建流媒体需接入付费服务 Mux，仅当客户明确要求时再议）。
- 建模原则：拿不准的字段一律设为可选；字段命名谨慎（增删便宜，重命名需数据迁移）。

### FR-03 新闻 / 博客

- 文案全部由客户编写。
- 字段确定为：**标题、正文、封面图、发布日期**（不需要分类 / 标签 / 作者）。
- 单语言发布策略：**某篇新闻只写一种语言时，另一种语言的站点不显示该篇**。

### FR-04 联系表单

- 基础字段：姓名、邮箱、电话、留言，另需**文件上传**。
- 访客提交后：
  1. 发送邮件通知到客户指定邮箱；
  2. 提交记录（含附件）留存到 CMS 后台，供客户查阅历史询盘。
- 需有垃圾提交防护（拟用 Cloudflare Turnstile）。
- 询盘接收邮箱地址、是否自动回复确认信 —— **待确认**，见 open-questions.md #9。

### FR-05 内容自助维护（CMS）

- 客户员工（非技术人员）可自行修改：案例、新闻、页面文字与图片。
- 要求可视化编辑界面，无需接触代码。
- 后台编辑人员**不超过 3 人**（Sanity 免费档可容纳，无需额外费用）。

## 4. 非功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-01 | 托管成本 | 免费 / 低成本优先，目标月成本 ≈ 0（域名费除外） |
| NFR-02 | 可维护性 | 交付后较少维护：选成熟生态、依赖少、升级风险低 |
| NFR-03 | 性能 | 建筑类网站图片量大，图片走 CDN + 懒加载；目标 Lighthouse 性能分 ≥ 90 |
| NFR-04 | SEO | 双语言独立 URL + hreflang；英文 SEO 为主（中文主要服务华人客户阅读） |
| NFR-05 | 合规 | 遵守新西兰 Privacy Act 2020：需 Privacy Policy 页面；若加统计分析需 Cookie 提示 |
| NFR-06 | 响应式 | 桌面 / 平板 / 手机自适应 |

## 5. 已拍板决策记录

### 5.1 URL 双语方案 —— 已拍板

采用**语言前缀 URL**：英文为默认语言，中文使用 `/zh/...` 前缀（如 `/projects` 与 `/zh/projects`），并配置 hreflang 标签。

理由：

1. 搜索引擎按 URL 抓取，独立 URL 才能保证两种语言都被 Google 收录（单一 URL + JS 切换会导致另一种语言对搜索引擎不可见）；
2. 分享链接时语言随链接走（把中文案例页发给微信好友，打开即是中文）；
3. 收藏、刷新、前进后退行为符合预期；
4. 在 Next.js / Astro 中均为标准路由模式，实现成本与单一 URL 方案相当。

### 5.2 其他已确认结论

| 项目 | 结论 |
|---|---|
| 内容长期维护人 | 客户员工自己修改 → 必须引入可视化 Headless CMS |
| 托管预算 | 免费 / 低成本优先 |
| 技术维护模式 | 交付后较少维护 |
| 表单处理方式 | 邮件通知 + CMS 后台留存记录；表单含文件上传 |
| 新闻 / 博客模块 | 需要，文案由客户编写；字段=标题/正文/封面图/日期；单语言发布时另一语言不显示 |
| URL 双语方案 | 英文默认 + `/zh/` 前缀 + hreflang（详见 5.1） |
| 页面清单（暂定） | 首页 / 案例 / 新闻 / 团队 / 服务 / 联系 |
| 设计稿 | 由客户提供；开发阶段使用占位图与占位文案 |
| 域名 | 由客户持有（避免交接纠纷） |
| 案例字段与筛选 | 已定稿，见 FR-02；数量级不超过 100 个；按项目类型筛选 |
| 案例视频方案 | 第三方平台链接嵌入（YouTube/Vimeo/Bilibili），不自建托管 |
| 后台编辑人数 | 不超过 3 人 |
| 技术栈 | 方案 A：Next.js + TypeScript + Tailwind + Sanity + Vercel + Resend + Turnstile（2026-10-08 拍板，详见 tech-stack.md） |
